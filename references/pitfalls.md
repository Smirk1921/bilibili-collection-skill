# 实战踩坑清单（遇到异常先查这里）

## 步骤1 抓取

| 问题 | 现象 | 解法 |
|---|---|---|
| 收藏夹接口"成功但没数据" | `code=0, message="OK", data=null` | **未登录或无权限就是这样返回的，不是接口坏了**。判断成功的条件是 `code==0 且 data 非空` |
| 写接口被误判为登录失效 | 写操作报"data=null（登录态失效）" | 写接口成功后**本来就返回 `data=null`**，必须走 `allow_null=True` |
| 分区名拿不到 | `tname` / `tname_v2` 恒为空字符串 | 只有数字 `tid` / `tid_v2`。分区名要自己反查，见 `methods-fetch.md` |
| 冷门分区查不到名字 | 排行榜只覆盖热门分区 | 用 `/x/web-interface/archive/related` 按视频逐个补——相关视频与本视频同分区 |
| 映射表被限流清空 | 某次采集返回 `-352`，结果反而变少 | 采用**合并式更新**：新采集结果合并进已有映射，不清空 |
| 富化中途被打断 | 跑到一半退出 | 结果每 50 条增量落盘，直接重跑会自动续传 |
| 失效稿件被当成"无标签" | 被删除的视频混进待分类 | 用业务码识别（`62002` / `-404` / `-403` / `-110`），标记为永久不可用，不再重试 |
| 并发调太高被限流 | 出现 `-412` / `-509` | `read_workers` 实测 3 稳定，调高收益有限 |

## 步骤2 分类

| 问题 | 现象 | 解法 |
|---|---|---|
| `galgame` 标签被当成百合 | 男性向 galgame 被归进百合 | **载体 ≠ 题材**。百合必须有明确信号（百合/GL/yuri/具体作品名），见 `BAIHE_SIGNAL` |
| `GL` 正则误匹配 | 简介里的 `WebGL2` / `GLSL` 命中百合 | 正则必须加词边界：`(?<![A-Za-z])GL(?![A-Za-z])` |
| `MAD` 正则误匹配 | 英文单词里的 `Mad` 命中，把动漫解析和电竞赛事复盘判成 MAD | `MAD` 必须**大小写敏感且加词边界**：`(?-i:\bMAD\b)` |
| 弱词产生假阳性 | 「对话**技巧**」把角色分析判成攻略；「放到这个**合集**里」把实况判成剪切 | 规则里只放指向性强的词，不用「技巧」「怎么」「合集」这类泛词 |
| 分区选错导致体裁错 | AI 动画 MV 被投到「工程机械」分区 | **让 `strong` 层（UP主 明确声明）优先于分区**——UP主 会选错分区，但不会写错"二次创作" |
| 余弦相似度分不出好坏 | 得分普遍落在 0.05~0.3，无法设阈值 | 改用 **IDF 加权覆盖率**：条目特征标签有多大比例能在该收藏夹找到，天然落在 [0,1] |
| 单视频画像被稀释 | 视频只有 5~10 个标签，与整个收藏夹做余弦必然很低 | 同上，用覆盖率而不是余弦 |
| 从已整理好的收藏夹乱挪 | 条目被移出用户精心分好的夹 | `reorg_margin`：往外挪需要目标明显更优，否则维持现状 |
| 样本太少的收藏夹立类 | 1~2 条视频的收藏夹成了分类目标，画像不可信 | `min_collection_size` 默认 3，低于此值不参与 |
| `profiles.json` 的 `top_tags` 恒为空 | 排查画像时发现标签列表是空的 | 历史 bug：`most_common()[:0]` 把结果全切掉了。已修 |
| 类目名丢了编码前缀 | 新建的收藏夹叫 `MAD` 而不是 `A01 体裁-MAD` | 规则表里写的是短标签，落盘前必须经 `taxonomy.resolve()` 换成带编码的类目名 |
| 重命名了用户的收藏夹 | 用户原有的「缺氧」变成了「B02 主题-缺氧」 | `_target_name()`：**已有同名收藏夹一律复用原名**，编码名只用于新建 |

## 步骤3 复核

| 问题 | 现象 | 解法 |
|---|---|---|
| 只给标题就复核 | 准确率上不去 | 必须给「标题+作者+原生分类+标签+简介+当前收藏夹」，简介信息量最大 |
| 子代理输出格式混乱 | 竖线/逗号混用、漏列、加粗、行首序号 | `_norm_rows()` 自动修复，修不了的记进报告而不是静默丢弃 |
| 置信度写成百分数 | `90` 而不是 `0.9` | 解析时大于 1 自动除以 100 |
| 复核结果按序号索引 | 中间步骤顺序一变就全错位 | **一律按 `item_id` 索引**，不要用数组下标 |
| **复核结果被追加而不是覆盖** | 人工改对了，计划里却同时出现规则判错的目标和人工修正的目标 | 复核是**权威修正**，必须 `decisions[iid] = {...}` **覆盖** L1 判定。实测这个 bug 在 L1 判定少时不会暴露，规则判定变多后才炸出来 |
| **测试 merge 冲掉了正式结果** | 拿一个测试批次跑 merge，把 346 条人工复核结果覆盖成 4 条 | `merge` 已加防护：新结果远少于已有标签时拒绝覆盖，需显式 `--force`。**测试时先把结果文件挪出 `step3/results/`** |

## 步骤5 增量

| 问题 | 现象 | 解法 |
|---|---|---|
| 失效/待确认条目被反复当成"新增" | 每次 `detect` 都报"新增 N 条" | 这些条目**也要写进分类总表**（`targets` 为空即可），否则基准里没有它们，差集永远非空 |

## 步骤4 写入

| 问题 | 现象 | 解法 |
|---|---|---|
| Excel 占用了报告文件 | `PermissionError` 导致整个报告步骤失败 | `_save()` 捕获后改存带时间戳的名字，不中断流程 |
| 收藏夹名过长 | 客户端显示被截断 | `MAX_NAME_LEN = 40`，构建时校验 |
| 想撤销 | — | `rollback.py --confirm` 按日志反向操作；新建的收藏夹只列出名字由用户手动删 |

## 通用

- **一切写入类操作前必须备份并向用户确认**
- **凭据只存本地配置文件**（`scripts/local_config.json` / `scripts/bilibili_cookies.json`），
  绝不写进任何产出物或汇报文本
- **不要绕过 dry-run**：`apply_collections.py` / `rollback.py` 不带 `--confirm` 时
  只打印预览，这是有意设计的
- 平台接口随时可能变。遇到解析不出字段时，先看 `data/` 里的原始返回，
  再决定是改代码还是走降级路径
