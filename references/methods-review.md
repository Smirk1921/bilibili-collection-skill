# 步骤3：复核——为什么必须做，以及怎么做

## 为什么必须复核

实测结论：**纯规则分类的准确率上限约 85%**。剩下 15% 的错误来自三个根因：

| 根因 | 实例 |
|---|---|
| 标签会误导 | `galgame` 标签被当成 `百合` 的同义词，实际一个是载体一个是题材 |
| 分区是 UP主 自选的，会选错 | 一个 AI 动画 MV 被投到了「工程机械」分区 |
| 中文弱词产生假阳性 | 「对话**技巧**」把角色分析误判成攻略；「放到这个**合集**里面」把实况误判成剪切 |

所以流程是：**规则给基线，AI 带上完整上下文逐条复核**。

## 批次协议

```
python scripts/review_tools.py prepare --size 30   # 切分 -> step3/batches/batch_NNN.txt
```

每个批次文件包含候选类目清单和逐条信息。**必须让复核者看到这些字段**：

- `标题` —— 主要依据
- `作者` —— 系列作品的强信号
- `原生分类` —— B站分区名，对体裁指示性强
- `标签` —— 参考，但**不要单独依赖它**（见上面的根因）
- `简介` —— 信息量最大。实测 332/381 条有简介，中位数 162 字，
  UP主 通常会在里面直接写明体裁（"攻略""教学""二次创作""MV"）
- `当前收藏夹` —— 已有归属
- `L1 判定` 与 `L1 得分` —— 规则给出的基线，供参考与推翻

只给标题会让复核退化成猜测。

## 结果格式

复核者把结果写入 `step3/results/batch_NNN.txt`，每行一条：

```
<item_id> | <目标分类，多个用 + 连接> | <置信度 0-1> | <判断依据>
```

示例：

```
BV1GJ411x7h7 | A01 体裁-MAD + B05 主题-AI · 算法 | 0.9 | 以AI为题材的二创动画，简介写明"非营利个人二次创作"
BV1xx411c7mD | 待定 | 0 | 标题与简介都看不出内容
```

判不准就写「待定」，**不要留空、不要硬猜**。

## 格式容错

`merge` 会自动修复这些常见问题，而不是直接丢弃：

- 竖线 `|` 与 `｜` 混用，或误用逗号分隔
- 行首的 `1.` `1、` `1)` 等序号
- markdown 加粗标记 `**`
- 置信度写成百分数（`90` → `0.9`）
- 目标分类之间用 `+` `＋` `,` `，` `/` `、` 任意一种分隔

修不了的行会记进 `step3/change_report.txt`，**不会静默跳过**。

## 汇总与回写

```
python scripts/review_tools.py merge              # -> step3/review_labels.json + change_report.txt
python scripts/review_tools.py apply --confirm    # 回写 step2/preclassification.json（先备份）
```

`change_report.txt` 会列出**与 L1 判定不同的每一条**（原判定 → 复核后 → 依据），
这是给用户看的关键产物——用户就是靠它判断复核质量的。
